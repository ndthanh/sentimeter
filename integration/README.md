# Sentimeter backend handoff — v1

This implementation uses AG-UI wire events for the agent run and an application-level transcript interface for STT. It is a bounded AG-UI profile, not an implementation of every AG-UI feature. UI remains English, transcript/audio Vietnamese. Source records and all personal identifiers are fictional demo fixtures.

## Run locally
`python3 -m http.server 4289 --directory dist`
Open http://localhost:4289. The Sentimeter S icon starts, pauses and resumes playback. Quynh / Chi is the default voice pair. Settings contains the voice selector, guided cursor toggle and reset. Guided cursor is enabled by default; turn it off for manual Accept, verification, classification, Hold, Resume and follow-up. Two selectable audio variants each have their own cue manifest. System cards remain hidden until all four classification levels are selected. The supplied Rewards path runs the audio scenario; all fabricated banking paths run read-only sample checks when no call is active. Changing a parent selection clears its descendants. Call history is three fictional, expandable records.

## Frontend globals
`window.sentimeter` exports the interface in contracts.ts. `setMode('live')` cancels demo playback, scheduled cursor gestures and simulated lookups. Backend APIs never invoke ElevenLabs: generated MP3s are static assets. No ElevenLabs key is shipped in dist.

### STT ingestion
```js
window.sentimeter.ingestTranscript({
  id: 'seg-001', callId: window.sentimeter.callId,
  speaker: 'customer', text: 'Chị chưa được cộng điểm.',
  revision: 0, isFinal: false, startMs: 15000, endMs: 18000
});
window.sentimeter.ingestTranscript({
  id: 'seg-001', callId: window.sentimeter.callId,
  speaker: 'customer', text: 'Chị chưa được cộng điểm cho giao dịch Trip.com.',
  revision: 1, isFinal: true, startMs: 15000, endMs: 20000
});
```
Segment IDs are unique within a call. Updates require strictly increasing revisions. An older/equal revision is ignored. A final segment cannot revert to partial; a higher-revision final correction replaces it. Only final segments enter model messages/context. All updates appear in the Vietnamese transcript. Values are HTML-escaped. Wrong call IDs are rejected without state mutation. startMs/endMs are call-relative milliseconds.

`sentimeter:context-ready` fires on accepted final/corrected-final segments, carrying a RunAgentInput. Debounce/coalesce at your gateway; do not start an agent run on every partial segment. External operator speech is user/context observation, not an assistant message generated by the model. Real PII filtering belongs at the server boundary before sending to a model.

### AG-UI POST/SSE
```js
const input = window.sentimeter.getRunInput();
await window.sentimeter.connectAgent({url: '/api/agent', input});
```
The endpoint is supplied by your backend; no such route is deployed in this static draft. Send a JSON RunAgentInput and respond `Content-Type: text/event-stream`. Example frame:

```
data: {"type":"RUN_STARTED","threadId":"SM-1027-084","runId":"same-as-input-runId"}

```
Then send STATE_SNAPSHOT (AgentState), STEP_STARTED/FINISHED, TOOL_CALL_* and STATE_DELTA as work proceeds, followed by RUN_FINISHED or RUN_ERROR. Use `metadata.eventId` for event deduplication. threadId must match callId and runId must match the submitted input. SSE transport handles UTF-8 streaming, CRLF, multiline data and chunk boundaries. An unexpected EOF, malformed frame or incompatible patch produces a connection error; automatic retries are deliberately not issued. Reconnect through a new run and full snapshot.

Alternatively use your own SDK/transport:
```js
window.sentimeter.setMode('live');
window.sentimeter.receiveEvent(event, {callId, runId});
```
Pass the original run scope on EVERY callback. Events for stale runs are rejected; resetting cancels the fetch and invalidates the prior connection epoch. Do not feed detached old callbacks without scope. New RUN_STARTED replaces the active run. State events outside a run are ignored. Snapshot validation and patch application are atomic; incompatible data throws and should trigger resync.

### Shared state profile
See AgentState in contracts.ts and `createAgentState` in dist/bridge.js. Snapshots contain cards, agents, recommendation and signals. Delta supports top-level add/replace at `/cards`, `/agents`, `/recommendation` and `/signals`. This is an explicit subset of RFC6902: nested/other operations are rejected; send a fresh snapshot or replace the complete field. The server remains authoritative. Agent activity renders from the agents array, not from hidden model reasoning. STEP/TOOL events appear in the event inspector.

The current renderer supports the Rewards sources and the sample routes in dist/workflows.js; backend can control their content and completion order, while approved workflow requirements remain server-side. A future multi-topic catalog requires versioned new card definitions. `recommendation` must remain null until the backend has sufficient evidence. An error must not be represented as an eligibility rejection.

### Operator actions
```js
window.addEventListener('sentimeter:action', ({detail}) => {
  // POST detail to your action endpoint; use detail.id as idempotency key.
});
```
Actions include accept_call, confirm_identity_field, select_classification, hold_call, resume_call, end_call and create_followup_case. Backend must authorize identity confirmation and workflow actions; UI labels are not security assertions. `setCallState({callId, verified:{dob:true,id:true}})` can reflect verified state from the server. `followupConfirmed:true` updates the result only after server acknowledgement. Demo actions are local only. Operator note persistence is not implemented.

## Audio/cursor synchronization
Playback uses the selected variant's MP3 currentTime, not elapsed wall time. A requestAnimationFrame loop checks cue crossings; fired IDs prevent duplicates. Final events are also processed on audio ended. User demo pause freezes media and local simulation timers. Buffering does not advance media cues. Retry can replay a failed block; processed cue IDs prevent repeated side effects. Reset clears media, timers, transcript, run, cursor jobs and drafted notes.

Verification cursor prepositions 650 ms before the aligned confirmation sentence ends, then triggers the matching actual DOM button at the cue crossing. Dropdown gestures are an illustrative sequence launched after request capture, not claimed to match specific spoken words. Hold lookups start only after the hold action. Follow-up playback stops at customer consent, waits for registration and then continues. Guided mode automatically performs these gated actions; manual mode waits for user clicks.

Timing precision is bounded by browser scheduling and ElevenLabs alignment. The source alignment has been structurally checked, not independently judged for phonetic accuracy. Background-tab throttling can delay painting: use a foreground tab for presentation. Demo transcript shows the current utterance as speaking and marks it final at its timestamp boundary; this is simulated STT, not microphone transcription.

## Acceptance
Run `node integration/tests.mjs`. Check final-correction handling, duplicate/stale revisions, atomic invalid patches, Unicode SSE chunks, schema errors and distinct audio cues. Browser QA must cover the full guided call, manual verification gates, hold-only investigation, the follow-up gate, pause/resume and replay. Backend networking requires integration testing against your real gateway.

## Manual investigation
In demo mode with no call running, completing classification loads the workflow and performs read-only sample checks automatically. All catalog routes have fabricated evidence records. Completed cards open details. Changing classification, resetting, starting audio or entering live backend mode cancels outstanding sample callbacks. Manual checks never verify identity or execute blocking, payment, account-access or case-creation actions. Supported evidence IDs also include route-1-0 through route-4-3 for these sample catalogs.
